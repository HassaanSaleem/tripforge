# User Test Card: seed-0008

## Feature (one sentence)
A travel agent can create an account and agency, sign out, sign back in with email + password in the browser, and land in an agency workspace that greets them by their own name, their agency's name, and their role — while wrong passwords are refused and the traveler-facing view stays free of platform chrome.

## Prerequisites
- [ ] The live app stack is running and healthy at http://localhost:3000 (the implementer booted it)
- [ ] A Chromium browser is available via the Playwright MCP browser tools

## Prerequisite Verification Commands
```bash
curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/api/health   # should print 200
curl -s http://localhost:3000/api/health                                  # should contain "ok"
```

## Steps

All steps are browser actions executed with the Playwright MCP browser tools against the live stack. Every step MUST capture a screenshot into the evidence directory `.kitchenloop/uat-runs/seed-0008/`.

### Step 1: Landing page offers sign-in
**Browser action:** navigate to http://localhost:3000/
**Expected visible result:** a link "Sign in" and a link "Agency workspace"
**Expected NOT visible:** any error page or stack trace
**Screenshot:** save as step-1.png in the evidence directory

### Step 2: Anonymous visitor cannot use the workspace
**Browser action:** navigate to http://localhost:3000/workspace
**Expected visible result:** heading "Agency workspace" and text containing "agency membership" with a "Sign in" link
**Expected NOT visible:** "Signed in as"
**Screenshot:** save as step-2.png in the evidence directory

### Step 3: Self-serve sign-up creates account + agency and lands in the workspace
**Browser action:** navigate to http://localhost:3000/sign-up, then fill "Your name" with "Vera Verifier", fill "Email" with "uat-vera-0008@example.test", fill "Password" with "verify-atlas-42", fill "Agency name" with "Vera Verified Travel", then click "Create account & agency"
**Expected visible result:** the page URL becomes http://localhost:3000/workspace and the page shows "Vera Verifier", "Vera Verified Travel", and "owner"
**Expected NOT visible:** any long random identifier string in the greeting (the greeting must use the names above, not IDs)
**Screenshot:** save as step-3.png in the evidence directory

### Step 4: Sign out ends the session
**Browser action:** on the workspace page, click "Sign out"
**Expected visible result:** the page URL becomes http://localhost:3000/sign-in and a sign-in form (Email, Password) is shown
**Expected NOT visible:** "Vera Verifier"
**Screenshot:** save as step-4.png in the evidence directory

### Step 5: Wrong password is rejected gracefully (negative test)
**Browser action:** on http://localhost:3000/sign-in, fill "Email" with "uat-vera-0008@example.test", fill "Password" with "totally-wrong-99", then click "Sign in"
**Expected visible result:** the text "Invalid email or password." appears and the page URL is still http://localhost:3000/sign-in
**Expected NOT visible:** "Signed in as", any stack trace or raw error code
**Screenshot:** save as step-5.png in the evidence directory

### Step 6: Correct password signs the agent back in
**Browser action:** on http://localhost:3000/sign-in, fill "Email" with "uat-vera-0008@example.test", fill "Password" with "verify-atlas-42", then click "Sign in"
**Expected visible result:** the page URL becomes http://localhost:3000/workspace and the page shows "Vera Verifier", "Vera Verified Travel", and "owner", plus a "Sign out" button
**Expected NOT visible:** "Invalid email or password."
**Screenshot:** save as step-6.png in the evidence directory

### Step 7: Traveler-facing view stays free of platform and sign-in chrome
**Browser action:** navigate to http://localhost:3000/view
**Expected visible result:** heading "Your trip"
**Expected NOT visible:** "TripForge", "Trellis", "Sign in", "Sign out"
**Screenshot:** save as step-7.png in the evidence directory
