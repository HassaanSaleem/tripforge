# User Test Card: seed-0022

## Feature (one sentence)
An agent can register a licensed photo into their agency's media library, attach it to an itinerary's gallery and to a specific item, see both attachments in the workspace, and share the trip so a client sees the same photo and its caption on the branded proposal page — with no internal library details ever visible to the client.

## Prerequisites
- [ ] The TripForge compose stack is running (web on http://localhost:3000)
- [ ] Docker CLI available (the log review step uses it)

## Prerequisite Verification Commands
```bash
curl -sf http://localhost:3000/api/health    # should print an ok/health JSON
docker compose ps --format '{{.Name}} {{.Status}}' | grep -c running   # should print 2 or more
```

## Steps

> All browser steps run against http://localhost:3000 with the Playwright MCP
> browser tools. Save every screenshot into the evidence directory
> `.kitchenloop/uat-runs/seed-0022/`.

### Step 1: Create the agency account
**Browser action:** navigate to http://localhost:3000/sign-up, fill "Your name" with "Mira Media", fill "Email" with "uat22-agent@example.test", fill "Password" with "uat22-pass-123", fill "Agency name" with "UAT Gallery 22", click the "Create account & agency" button
**Expected visible result:** the browser lands on http://localhost:3000/workspace and the header shows "Mira Media" and "UAT Gallery 22"
**Expected NOT visible:** any error alert
**Screenshot:** save as step-1.png in the evidence directory

### Step 2: Register a media item in the content library
**Browser action:** in the "Your media" panel, select "Your upload" for "Source" (it is the default), select "Image" for "Kind" (it is the default), fill "Media URL" with "https://images.example.test/uat22-lisbon.jpg", fill "Alt text" with "UAT lisbon view", click "Add to library"
**Expected visible result:** a media card appears in "Your media" showing the text "UAT lisbon view" and a "Your upload" badge, with no page reload
**Expected NOT visible:** "No media yet"
**Screenshot:** save as step-2.png in the evidence directory

### Step 3: Draft an itinerary
**Browser action:** in the "Plan a trip" form, fill "Destination" with "Lisbon", "Check-in" with "2026-09-01", "Check-out" with "2026-09-03", "Adults" with "2", "Children" with "0", select "balanced" for "Trip style", fill "Budget" with "1000", select "hardCap" for "Budget mode", fill "Currency" with "USD", click "Draft itinerary", wait up to 90 seconds
**Expected visible result:** a drafted itinerary appears with day-by-day items; below it, the "Trips in your workspace" panel lists the new trip
**Expected NOT visible:** any error alert
**Screenshot:** save as step-3.png in the evidence directory

### Step 4: Open the trip and attach the photo to the gallery
**Browser action:** in "Trips in your workspace", click "Open" on the trip just drafted; once the trip view opens, find the "Gallery" section and its "+ Add to gallery" dropdown, select "UAT lisbon view" from it
**Expected visible result:** an image thumbnail appears in the Gallery section with a small "×" remove button on it
**Expected NOT visible:** "No gallery photos yet." (that text must be gone once the photo is attached)
**Screenshot:** save as step-4.png in the evidence directory

### Step 5: Attach the same photo to the first day's first item
**Browser action:** on "Day 1", find its first listed item, locate its "+ Add photo" dropdown directly below the item text, select "UAT lisbon view" from it
**Expected visible result:** a small image thumbnail appears next to that item (below its title), with its own small "×" remove button
**Expected NOT visible:** an error alert
**Screenshot:** save as step-5.png in the evidence directory

### Step 6: Share the trip with the client
**Browser action:** find the "Share with your client" section within the SAME opened trip view, click "Share with client"
**Expected visible result:** a link appears in a code element with the test id "share-url", starting with "http://localhost:3000/view/"
**Expected NOT visible:** any error alert
**Screenshot:** save as step-6.png in the evidence directory

### Step 7: Open the shared link exactly (no manual retyping)
**Browser action:** Do NOT read the link visually from the screenshot and do NOT type it by hand — transcription errors invalidate this step. Instead, use your browser tool's JavaScript-evaluation capability to run exactly this expression on the current page and capture its return value: `document.querySelector('[data-testid="share-url"]').textContent.trim()`. Then navigate the SAME browser tab directly to the exact string that expression returned.
**Expected visible result:** the page loads with the heading "UAT Gallery 22" (the agency name) visible near the top
**Expected NOT visible:** "isn't available" (that text means the wrong or a mistyped link was used — if you see it, re-run the JavaScript-evaluation step exactly as written and navigate again before recording a failure)
**Screenshot:** save as step-7.png in the evidence directory

### Step 8: The client sees the photo in the gallery and on the item, with its caption
**Browser action:** on the page loaded in Step 7, look for a gallery image near the top of the page and a second image next to the first listed item on "Day 1"
**Expected visible result:** BOTH images are visible; hovering or inspecting either one shows accessible/alt text reading "UAT lisbon view" (you may confirm this by checking the element's alt attribute rather than visually)
**Expected NOT visible:** any text reading "agent-upload", "your-upload", or "UAT Gallery 22" is fine to see (that is the agency's own brand name, expected), but the word "agent-upload" (the internal source label) must NOT appear anywhere in the page
**Screenshot:** save as step-8.png in the evidence directory

### Step 9: Compose-log review
```bash
docker compose logs --no-color | grep -E "ERROR|FATAL|Unhandled" | grep -v "duplicate key value violates unique constraint" | head -20
```
**Expected exit code:** 0 or 1 (grep finding nothing exits 1 — that is the PASS case)
**Expected output contains:** "" (empty output is the expected result)
**Expected output does NOT contain:** "FATAL"
