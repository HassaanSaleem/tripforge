# User Test Card: seed-0016

> This card verifies PR #31's bundle of three user-visible changes to the
> marketplace listing form (tickets seed-0016, seed-0009d-b, seed-0020) in one
> continuous journey — they share one page and one form.

## Feature (one sentence)
A seller's declared listing terms survive a refused submission exactly as typed, the license-fee field states its currency semantics before an itinerary is picked, and after licensing a trip the buyer's sell-form picker offers the new white-label copy immediately without a page reload.

## Prerequisites
- [ ] The TripForge compose stack is running (web on http://localhost:3000)
- [ ] Docker CLI available (the operator vetting steps and the log review use it)

## Prerequisite Verification Commands
```bash
curl -sf http://localhost:3000/api/health    # should print an ok/health JSON
docker compose ps --format '{{.Name}} {{.Status}}' | grep -c running   # should print 2 or more
```

> browser tools. Save every screenshot into the evidence directory

### Step 1: Create the SELLER agency account
**Browser action:** navigate to http://localhost:3000/sign-up, fill "Your name" with "Sana Seller", fill "Email" with "uat16-seller@example.test", fill "Password" with "uat16-pass-123", fill "Agency name" with "UAT Terra 16", click the "Create account & agency" button
**Expected visible result:** the browser lands on http://localhost:3000/workspace and the header shows "Sana Seller" and "UAT Terra 16"
**Expected NOT visible:** any error alert
**Screenshot:** save as step-1.png in the evidence directory

### Step 2: Draft an itinerary in the workspace
**Browser action:** on http://localhost:3000/workspace fill "Destination" with "Paris", "Check-in" with "2026-09-01", "Check-out" with "2026-09-04", "Adults" with "2", "Children" with "0", select "balanced" for "Trip style", fill "Budget" with "1000", select "hardCap" for "Budget mode", fill "Currency" with "USD", click "Draft itinerary", wait up to 90 seconds
**Expected visible result:** a drafted itinerary appears with day-by-day items and a "Budget summary" table
**Expected NOT visible:** "Could not reach the server"
**Screenshot:** save as step-2.png in the evidence directory

### Step 3: The fee field explains its currency BEFORE an itinerary is picked
**Browser action:** click the "Marketplace" link in the page header, then read the "List a finished itinerary" form WITHOUT selecting anything
**Expected visible result:** the fee field is labelled exactly "License fee" (no currency in the label) and directly below it the hint "Priced in the picked itinerary's own currency — pick one above." is visible
**Expected NOT visible:** "License fee (USD)"
**Screenshot:** save as step-3.png in the evidence directory

### Step 4: Picking an itinerary swaps the hint for the real currency
**Browser action:** in the "Itinerary" dropdown select the first real option (the drafted Paris trip)
**Expected visible result:** the fee field label becomes "License fee (USD)"
**Expected NOT visible:** "Priced in the picked itinerary's own currency — pick one above."
**Screenshot:** save as step-4.png in the evidence directory

### Step 5: Fill the listing terms, including a NON-DEFAULT revenue share
**Browser action:** fill "Listing title" with "Terra keeper UAT16", fill "License fee (USD)" with "200", fill "License terms" with "White-label permitted; keep attribution lineage.", fill "Revenue share %" with "7.5"
**Expected visible result:** the "Revenue share %" field shows "7.5"
**Expected NOT visible:** "10" in the "Revenue share %" field
**Screenshot:** save as step-5.png in the evidence directory

### Step 6: Listing BEFORE vetting is refused — and the declared terms MUST NOT change
**Browser action:** click "List it on the marketplace"
**Expected visible result:** an explanation containing "isn't vetted for the marketplace yet" AND the "Revenue share %" field STILL shows "7.5" (not 10), the "Listing title" still shows "Terra keeper UAT16", the fee still shows "200"
**Expected NOT visible:** "Listed — your trip is live on the marketplace above."
**Screenshot:** save as step-6.png in the evidence directory

### Step 7: The platform operator vets the seller agency
```bash
docker compose exec -T postgres psql -U tripforge -d tripforge -tAc "INSERT INTO agency_vetting (agency_id, vetted_by) SELECT id, 'uat-operator' FROM organization WHERE name = 'UAT Terra 16' ON CONFLICT (agency_id) DO NOTHING; SELECT count(*) FROM agency_vetting v JOIN organization o ON o.id = v.agency_id WHERE o.name = 'UAT Terra 16';"
```
**Expected exit code:** 0
**Expected output contains:** "1"
**Expected output does NOT contain:** "ERROR"

### Step 8: The vetted retry lists at the DECLARED terms, not the default
**Browser action:** click "List it on the marketplace" again (the form still holds the values from Step 5)
**Expected visible result:** "Listed — your trip is live on the marketplace above." AND a listing card titled "Terra keeper UAT16" appears in "Live listings" showing "200.00 USD" and "7.5% revenue share" and a "Your listing" badge
**Expected NOT visible:** "10% revenue share" on the "Terra keeper UAT16" card
