# User Test Card: seed-0013

## Feature (one sentence)
Every page ships a favicon, so the browser no longer logs a 404 for
`/favicon.ico` and the devtools console is clean on all surfaces.

## Prerequisites
- [ ] The TripForge stack is running and healthy

## Prerequisite Verification Commands
```bash
curl -s http://localhost:3000/api/health    # prints {"status":"ok","db":"up"}
```

## Steps

### Step 1: The favicon route serves an icon
```bash
curl -s -o /dev/null -w '%{http_code} %{content_type}' http://localhost:3000/favicon.ico
```
**Expected exit code:** 0
**Expected output contains:** "200" and "image/"
**Expected output does NOT contain:** "404"

### Step 2: Landing page loads with a clean console
**Browser action:** navigate to http://localhost:3000/ then read the browser console messages (error level)
**Expected visible result:** heading "TripForge"; zero console errors (no "Failed to load resource" lines)
**Expected NOT visible:** any console error mentioning favicon.ico or 404
**Screenshot:** save as step-2.png

### Step 3: Workspace page loads with a clean console
**Browser action:** navigate to http://localhost:3000/workspace then read the browser console messages (error level)
**Expected visible result:** heading "Agency workspace"; zero console errors
**Expected NOT visible:** any console error mentioning favicon.ico or 404
**Screenshot:** save as step-3.png

### Step 4: Client view loads with a clean console
**Browser action:** navigate to http://localhost:3000/view then read the browser console messages (error level)
**Expected visible result:** heading "Your trip"; zero console errors
**Expected NOT visible:** any console error mentioning favicon.ico or 404
**Screenshot:** save as step-4.png

### Step 5: Unknown routes still 404 gracefully (negative test)
```bash
curl -s -o /dev/null -w '%{http_code}' http://localhost:3000/no-such-page
```
**Expected exit code:** 0
**Expected output contains:** "404"
